# 몬스터 배틀 아레나 — 프로젝트 계획서

> **가제**: 몬스터 배틀 아레나 (Monster Battle Arena)
> **장르**: 턴제 몬스터 배틀 / 2D 캐주얼 RPG
> **한 줄 소개**: 몬스터를 모으고, 타입 상성을 읽으며, 한 판 3~5분 안에 끝나는 플래시 게임 감성의 미니 배틀 게임.
> **문서 버전**: v0.1 (2026-11-10)

---

## 1. 한 장 요약

| 항목 | 내용 |
|---|---|
| 플랫폼 | PC·모바일 웹 브라우저 (데스크톱 우선) |
| 기술 | TypeScript + Phaser 3 + Vite |
| 화면 | 480×270 도트풍 2D, 16:9 정수배 스케일 |
| 조작 | 마우스/터치 클릭 + 키보드 방향키·Z/X |
| 핵심 루프 | 몬스터 선택 → 배틀 → 승리 → 보상/해금 → 다음 배틀 |
| 1회 플레이 | 10~15분 (스테이지 5개 + 보스 1개) |
| MVP 범위 | 몬스터 6종, 기술 12개, 타입 4종, 1v1 턴제 배틀, 스테이지 6개 |
| 개발 기간 | 1인 기준 약 2주 (10 영업일) |
| 저장 | 브라우저 localStorage (서버 없음) |
| 배포 | GitHub Pages 또는 itch.io |

### 성공 기준 (MVP)
1. 처음 실행한 사람이 **설명 없이 30초 안에 첫 배틀에 진입**한다.
2. 배틀 1판이 **3~5분** 안에 끝나고, 승패가 납득 가능하다.
3. 새로고침해도 진행 상황이 유지된다.
4. 콘솔 에러 0건, 모바일 브라우저에서 터치만으로 플레이 가능하다.

## 2. 게임 컨셉

### 2.1 무엇을 하는 게임인가
플레이어는 몬스터 트레이너가 되어 짧은 스테이지를 차례로 클리어한다. 각 배틀은 **턴제 1대1**이며, 플레이어는 매 턴 "기술 4개 중 하나"를 고른다. 상성·속도·HP 관리라는 단순한 선택지만으로 긴장감을 만든다.

### 2.2 왜 이 범위인가
- 포켓몬식 재미의 핵심은 **수집 + 상성 + 성장**이며, 그래픽·맵·스토리는 없어도 성립한다.
- "플래시 게임 수준"에 맞춰 **1개 화면, 1개 전투 규칙, 짧은 세션**에 집중한다.
- 3D, 실시간 액션, 멀티플레이, 서버 저장은 **명시적 비목표**로 둔다.

### 2.3 차별점 / 톤
- 귀여운 도트 몬스터 + 큼직한 UI + 짧고 경쾌한 효과음.
- 타입 상성을 **색과 아이콘으로 즉시 이해**시킨다(불=빨강, 물=파랑, 풀=초록, 노말=회색).
- 실패해도 즉시 재도전. 패배 시 "상성 힌트"를 보여줘 학습을 돕는다.
- **IP 안전**: 포켓몬의 이름·이미지·기술명을 쓰지 않고 오리지널 몬스터/기술만 사용한다.

### 2.4 비목표 (이번 버전에서 하지 않음)
- 멀티플레이, 랭킹, 계정, 서버
- 오픈 월드/탐험, NPC 대화, 스토리 분기
- 몬스터 진화·교배·알 부화
- 실시간 액션 배틀, 3D, 고해상도 일러스트
- 사운드 작곡(무료 에셋 또는 간단한 효과음만)

## 4. 기술 스택과 아키텍처

### 4.1 스택
- **Phaser 3** — 2D 렌더링, 씬 관리, 입력, 트윈, 사운드
- **TypeScript** — 배틀 로직 타입 안정성
- **Vite** — 개발 서버/빌드
- **Vitest** — 배틀 계산 유닛 테스트
- **ESLint + Prettier** — 코드 스타일
- 서버/DB 없음, 저장은 `localStorage`

> 대안: 순수 Canvas 2D + 자체 루프. 의존성이 줄지만 씬/입력/사운드 관리 비용이 늘어나므로 Phaser를 기본안으로 채택한다.

### 4.2 설계 원칙
1. **로직과 표현 분리**: 배틀 계산은 Phaser를 모르는 순수 함수/클래스로 작성하고, 씬은 결과를 연출만 한다.
2. **데이터 주도**: 몬스터·기술·스테이지는 JSON/TS 데이터로 분리해 코드 수정 없이 추가한다.
3. **시드 기반 난수**: 테스트 재현성을 위해 배틀 난수는 주입 가능한 RNG를 사용한다.
4. **단방향 상태**: 배틀 상태는 한 곳에서만 변경하고, UI는 상태를 읽어 갱신한다.

### 4.3 씬 구성
```
BootScene      에셋 로드, 폰트/설정 초기화
TitleScene     타이틀, 이어하기/새로 시작
SelectScene    보유 몬스터 확인 및 출전 선택
WorldScene     스테이지 목록/진행도 (간단한 맵 UI)
BattleScene    배틀 연출 + 커맨드 UI
ResultScene    승패, 보상, 다음 스테이지
```

## 5. 코어 게임 루프

```
[타이틀]
   ↓ 새 게임 / 이어하기
[몬스터 선택]  ← 스타터 3종 중 1종 선택 (최초 1회)
   ↓
[월드/스테이지 목록]
   ↓ 스테이지 진입
[배틀] ── 패배 → 재도전 (스테이지 유지)
   │ 승리
   ↓
[결과] → 보상(새 몬스터 해금/레벨업) → 다음 스테이지
   ↓
[보스전] → 엔딩 → 자유 배틀(확장)
```

- 배틀 중 이탈해도 스테이지 시작 상태로 복귀(배틀은 원자적).
- 스테이지 클리어 즉시 저장.
- 패배 시 보상 없음, 재도전 무제한.

## 6. 배틀 시스템 상세

### 6.1 기본 규칙
- **1대1 턴제**. 각 몬스터는 기술 4개를 가진다.
- 턴마다 플레이어가 기술 1개를 선택하고, 적 AI도 동시에 선택한다.
- **스피드가 높은 쪽이 먼저** 행동. 동률이면 난수로 결정.
- 기술 명중 판정(명중률) → 데미지 계산 → HP 반영 → 기절 판정.
- 한쪽 HP가 0이 되면 배틀 종료.
- **PP 개념 없음** (MVP 단순화). 대신 강한 기술은 명중률을 낮게 설정해 균형을 맞춘다.
- 아이템/도망/교체는 MVP에서 제외 (Phase 2).

### 6.2 스탯
| 스탯 | 의미 | 범위(레벨 1~20) |
|---|---|---|
| HP | 최대 체력 | 30~120 |
| ATK | 공격력 | 10~60 |
| DEF | 방어력 | 10~60 |
| SPD | 속도 | 10~60 |

- 레벨업 시 스탯 증가: `stat = floor(base * (1 + 0.06 * (level - 1)))`
- HP는 `floor(baseHP * (1 + 0.08 * (level - 1)))`로 조금 더 빠르게 성장.

### 6.3 데미지 공식
```
base = floor( ( (2 * level / 5 + 2) * power * atk / def ) / 50 + 2 )
damage = floor( base * typeMultiplier * critMultiplier * random(0.85 ~ 1.00) )
```
- `typeMultiplier`: 2.0(효과 굉장함) / 1.0(보통) / 0.5(효과 별로)
- `critMultiplier`: 1.5 (확률 1/16)
- 최소 데미지 1 보장
- 데미지는 정수, HP는 0 미만으로 내려가지 않음

### 6.4 타입 상성 (4타입)
| 공격 ↓ / 방어 → | 불 | 물 | 풀 | 노말 |
|---|---|---|---|---|
| **불** | 0.5 | 0.5 | **2.0** | 1.0 |
| **물** | **2.0** | 0.5 | 0.5 | 1.0 |
| **풀** | 0.5 | **2.0** | 0.5 | 1.0 |
| **노말** | 1.0 | 1.0 | 1.0 | 1.0 |

- 삼각 구도(불→풀→물→불)로 직관적으로 이해 가능.
- 노말은 안정적이지만 상성 이점이 없음.

### 6.5 턴 처리 순서 (의사 코드)
```
1. 양측 행동 선택 (플레이어 입력 / AI)
2. SPD 비교로 행동 순서 결정
3. 선공 행동 resolve:
   a. 명중 판정 실패 → "빗나감" 연출, 종료
   b. 데미지 계산 및 적용
   c. 대상 HP <= 0 → 기절, 배틀 종료
4. 후공 생존 시 후공 행동 resolve (3과 동일)
5. 턴 종료 처리(상태이상 없음 MVP) → 다음 턴
```

### 6.6 적 AI (MVP)
- 기본: **가장 효과적인 기술**을 선택 (기대 데미지 최대).
- 20% 확률로 무작위 기술 선택 → 예측 불가능성 부여.
- HP 30% 이하일 때 회복 기술이 있으면 사용(Phase 2). MVP는 공격만.
- AI도 동일한 데미지 공식을 사용해 공정성을 유지.

### 6.7 승패 및 보상
- 승리: 스테이지 클리어, EXP 획득, 필요 시 새 몬스터 해금.
- EXP: `획득 EXP = 적 레벨 * 8 + 20`. 레벨업 필요 EXP: `level * 25`.
- 패배: 재도전. 3회 연속 패배 시 "상성 힌트" 팝업 노출.
- 보스는 플레이어보다 2레벨 높게 설정하되, 상성으로 공략 가능하게 설계.

## 8. 화면과 UX

### 8.1 화면 목록
1. **타이틀**: 로고, `새 게임` / `이어하기`, 버전 표시.
2. **스타터 선택**: 3종 카드, 타입 아이콘, 스탯 미리보기.
3. **월드/스테이지 목록**: 6개 노드, 클리어 표시, 현재 위치 강조.
4. **배틀**: 상단 적 정보(이름/Lv/HP바), 하단 아군 정보, 하단 커맨드 패널(기술 4개).
5. **결과**: 승패 배너, 획득 EXP, 해금 알림, `다음` / `재도전`.
6. **설정(간단)**: 사운드 On/Off, 저장 초기화.

### 8.2 배틀 화면 레이아웃 (480×270)
```
┌──────────────────────────────────────────┐
│  [적 이름 Lv.5]            HP ██████░░   │  상단 20%
│              (적 스프라이트)              │
│                                          │
│   (아군 스프라이트)                       │  중앙 55%
│                                          │
│ [아군 이름 Lv.5]  HP ████████░░  EXP ▁▂  │
├──────────────────────────────────────────┤
│  ▶ 불꽃 발톱   ▶ 불티 폭발                │  하단 25%
│  ▶ 몸통 박치기 ▶ (비어 있음)              │
└──────────────────────────────────────────┘
```
- 기술 버튼에 **타입 색**과 **상성 배지(◎/△)** 를 표시.
- 키보드: 방향키로 커서, Z/Enter 확정, X 취소.
- 터치: 버튼 최소 44px, 오조작 방지 위해 확인 단계 없이 즉시 실행하되 연출로 피드백.

### 8.3 연출 (플래시 게임 감성)
- 공격 시: 공격자 앞으로 8px 돌진 → 대상 흔들림 + 흰색 플래시 → 데미지 숫자 팝업.
- 효과 굉장함: 화면 살짝 흔들림 + 강한 색 플래시.
- 기절: 스프라이트 아래로 슬라이드 + 페이드.
- HP바는 0.3초 트윈으로 감소(즉시 0으로 튀지 않게).
- 모든 연출은 **스킵 가능**하거나 0.5초 이내로 짧게.

## 9. 비주얼과 사운드

### 9.1 아트 방향
- 해상도 480×270, 정수배 확대, 픽셀 아트.
- 몬스터: 64×64, 2프레임 idle(숨쉬기), 공격은 트윈으로 대체.
- 배경: 480×270 1장, 스테이지별 색조 변경으로 재사용.
- UI: 9-slice 패널, 도트 폰트(예: 둥근모꼴/Galmuri, 라이선스 확인).

### 9.2 에셋 확보 전략
1. **1차**: 임시 도형/이모지 플레이스홀더로 로직 완성.
2. **2차**: 무료 에셋(Kenney, OpenGameArt, itch.io 무료 팩)으로 교체.
3. **3차**: 필요 시 AI 생성 또는 직접 도트 작업.
- 모든 에셋은 `public/assets/CREDITS.md`에 출처·라이선스 기록.

### 9.3 사운드
- BGM 1곡(루프), 효과음 6종(선택, 명중, 빗나감, 효과 굉장, 기절, 승리).
- 무료/CC0 에셋 우선. 볼륨 기본 50%, 설정에서 On/Off.
- 모바일 자동재생 정책 대응: 첫 입력 후 오디오 컨텍스트 활성화.

## 10. 데이터 설계

### 10.1 타입 정의 (예시)
```ts
export type ElementType = 'fire' | 'water' | 'grass' | 'normal';

export interface Move {
  id: string;
  name: string;
  type: ElementType;
  power: number;        // 0이면 변화기
  accuracy: number;     // 0~100
  description: string;
}

export interface MonsterSpecies {
  id: string;
  name: string;
  type: ElementType;
  base: { hp: number; atk: number; def: number; spd: number };
  moveIds: string[];    // 최대 4개
  spriteKey: string;
}

export interface MonsterInstance {
  speciesId: string;
  level: number;
  exp: number;
  currentHp: number;
}

export interface Stage {
  id: number;
  name: string;
  enemySpeciesId: string;
  enemyLevel: number;
  rewardExp: number;
  unlockSpeciesId?: string;
  backgroundKey: string;
}
```

### 10.2 배틀 상태
```ts
export interface BattleState {
  player: MonsterInstance;
  enemy: MonsterInstance;
  turn: number;
  phase: 'select' | 'resolving' | 'finished';
  winner: 'player' | 'enemy' | null;
  log: string[];
}
```

### 10.3 저장 데이터
```ts
export interface SaveData {
  version: 1;
  starterId: string;
  owned: MonsterInstance[];
  currentStage: number;   // 1-based, 클리어한 마지막 스테이지
  unlockedSpecies: string[];
  settings: { sound: boolean };
  updatedAt: string;
}
```
- 키: `monster-arena.save.v1`
- 저장 시점: 스타터 선택, 스테이지 클리어, 설정 변경
- 손상된 JSON은 감지 시 새 게임 유도(기존 데이터 백업 키에 보관)

## 11. 개발 계획 (1인, 10 영업일)

### Phase 0 — 준비 (0.5일)
- [ ] Vite + TS + Phaser 프로젝트 생성
- [ ] 해상도/스케일/입력 설정, 빈 씬 6개 생성

### Phase 1 — 배틀 코어 (2.5일)
- [ ] 타입/데이터 정의, 몬스터 6종·기술 12개 데이터 작성
- [ ] 데미지·명중·스피드·승패 계산 엔진 구현
- [ ] 시드 RNG 및 유닛 테스트(상성, 크리티컬, 최소 데미지, 선공)
- [ ] 적 AI(기대 데미지 최대 + 20% 랜덤)

### Phase 2 — 배틀 화면 (2일)
- [ ] HP바/EXP바/커맨드 패널 UI
- [ ] 턴 연출(돌진, 흔들림, 데미지 팝업, 기절)
- [ ] 키보드/터치 입력, 연출 중 입력 잠금
- [ ] 로그 텍스트("효과가 굉장했다!")

### Phase 3 — 메타 루프 (2일)
- [ ] 타이틀 → 스타터 선택 → 스테이지 목록 → 배틀 → 결과 연결
- [ ] 저장/불러오기, 이어하기
- [ ] 레벨업/EXP/해금 처리

### Phase 4 — 콘텐츠와 폴리시 (2일)
- [ ] 스테이지 6개 밸런싱(플레이 테스트 3회 이상)
- [ ] 사운드, 배경, 스프라이트 교체
- [ ] 모바일 레이아웃/터치 검증
- [ ] 버그 수정, 콘솔 에러 제거

### Phase 5 — 배포 (1일)
- [ ] 프로덕션 빌드, GitHub Pages/itch.io 업로드
- [ ] README, 플레이 링크, 크레딧 정리

## 13. 완료 기준 (Definition of Done)

MVP는 아래를 **모두** 만족할 때 완료로 본다.

- [ ] 새 게임 시작 → 스타터 선택 → 스테이지 1 진입이 끊김 없이 동작
- [ ] 배틀에서 기술 선택, 명중/빗나감, 상성, 크리티컬, 기절이 모두 동작
- [ ] 승리 시 EXP/레벨업/해금이 반영되고 저장된다
- [ ] 패배 시 재도전이 가능하고 진행이 깨지지 않는다
- [ ] 새로고침 후 이어하기로 진행 상황이 복원된다
- [ ] 스테이지 6개를 순서대로 클리어할 수 있다
- [ ] 키보드와 터치로 전체 플레이가 가능하다
- [ ] 콘솔 에러/경고 0건, 빌드 성공
- [ ] 배포 URL에서 실제 플레이 가능
- [ ] 크레딧/라이선스 문서 존재
