# 🍕 피자 만들기 미니 게임 — 프로젝트 계획서

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (초안) |
| 작성일 | 2026-11-10 |
| 프로젝트명 | Pizza Rush (가칭) |
| 장르 | 2D 캐주얼 타이쿤 / 조리 시뮬레이션 |

## 1. 한 줄 소개

> 주문서대로 도우 위에 소스·치즈·토핑을 올리고, 오븐에서 딱 맞게 구워 손님에게 서빙하는 초간단 2D 피자 타이쿤 게임.

플래시 게임처럼 **클릭 몇 번으로 바로 시작**하고, 한 판이 짧으며, 점수 갱신을 노리고 다시 하게 되는 구조를 목표로 한다.

---

## 2. 목표와 범위

### 2.1 프로젝트 목표
- 설치 없이 브라우저에서 즉시 플레이 가능한 2D 미니 게임 완성
- "만들기 → 굽기 → 서빙"의 명확한 손맛(피드백) 구현
- 그래픽 리소스 없이도 도형/간단한 스프라이트로 완성도 있는 비주얼 확보

### 2.2 MVP에 포함 (Must)
- [ ] 주문 표시 및 레시피 판정
- [ ] 도우 → 소스 → 치즈 → 토핑 → 오븐 → 서빙의 전체 플레이 루프
- [ ] 오븐 굽기 타이머(과소/적정/과다 굽기)
- [ ] 손님 만족도 및 팁 점수
- [ ] 점수 · 콤보 · 게임 오버 · 재시작
- [ ] 사운드 효과(선택: 간단한 Web Audio 합성음)

### 2.3 이번 범위에서 제외 (Nice to have / 이후)
- 멀티플레이, 서버 저장, 랭킹
- 스토리 모드, 캐릭터 육성
- 모바일 터치 최적화(구현은 하되 1차 목표 아님)
- 고해상도 일러스트, 애니메이션 컷신

### 2.4 명시적 비목표
- 리얼한 요리 시뮬레이션(물리, 온도 시뮬레이션 등)은 하지 않는다.
- 재료 수는 MVP 기준 **6종 이내**로 제한한다.

## 3. 타겟 유저 & 핵심 재미

- **타겟**: 가볍게 3~5분 즐길 캐주얼 게임을 찾는 일반 사용자
- **핵심 재미 (Core Fun)**
  1. 주문을 보고 머릿속으로 조합을 맞추는 **퍼즐적 재미**
  2. 굽기 게이지를 노려 맞추는 **타이밍 손맛**
  3. 연속 성공 시 쌓이는 **콤보의 쾌감**
  4. 실수(과다 토핑, 태운 피자)에 대한 **가벼운 리스크**

## 4. 게임 플레이 루프

```
[주문 접수] → [도우 선택] → [소스 바르기] → [치즈/토핑 올리기]
     → [오븐에 넣기 & 굽기 타이밍] → [커팅] → [서빙] → [평가/점수] → 다음 주문
```

### 4.1 단계별 상세

| 단계 | 조작 | 성공 조건 | 실패/감점 |
|---|---|---|---|
| 1. 주문 접수 | 자동 (주문서 표시) | — | 제한 시간 초과 시 손님 이탈 |
| 2. 도우 선택 | 클릭 | 주문과 같은 도우(기본/씬) | 다른 도우 선택 시 -10점 |
| 3. 소스 | 드래그(붓칠) | 주문 소스와 일치 | 누락 시 -15점 |
| 4. 치즈/토핑 | 클릭 또는 드래그앤드롭 | 주문 토핑 조합과 일치 | 개수 초과/오토핑 -10점 |
| 5. 오븐 | 버튼으로 넣고, 게이지 보고 꺼내기 | "적정" 구간에서 꺼내기 | 과소/과다 굽기 -20점 |
| 6. 커팅 | 클릭(4~8조각) | 주문 조각 수와 일치 | 불일치 -5점 |
| 7. 서빙 | 드래그로 손님에게 전달 | 위 조건 종합 판정 | — |

### 4.2 판정 & 점수 공식(안)

```
정확도 = (일치한 재료 수 / 주문 재료 수) × 100
굽기 보정 = 적정: ×1.0 / 약간 과소·과다: ×0.7 / 완전 실패: ×0.3
조각 보정 = 일치: ×1.0 / 불일치: ×0.8

기본 점수 = 100 × 정확도 × 굽기 보정 × 조각 보정
콤보 보너스 = 기본 점수 × (1 + 0.1 × 콤보 수)   // 콤보 최대 5
팁 = 기본 점수 × 0.2 (정확도 100%일 때만)
```

- 콤보는 **정확도 80% 이상**일 때 +1, 실패 시 0으로 초기화
- 손님 만족도는 3단계 이모지(😡 😐 😍)로 즉시 피드백

## 6. 게임 시스템 상세

### 6.1 주문 생성
- 스테이지가 오를수록 **재료 수 +1**, **제한 시간 -3초**
- 레시피 풀에서 랜덤 선택하되, 이전 주문과 완전히 같지 않게
- 토핑은 0~3종, 각 1~2개

### 6.2 조작 방식
- **클릭**: 재료 선택, 오븐 버튼, 커팅
- **드래그앤드롭**: 토핑을 도우 위로 끌어다 놓기, 완성 피자를 손님에게 서빙
- **드래그(붓칠)**: 소스 바르기(간단히 도우 위 클릭·드래그하면 칠해짐)
- 모든 상호작용에 **즉시 시각/청각 피드백** 필수

### 6.3 오븐 굽기
- 오븐에 넣으면 게이지가 0→100으로 증가 (약 6초)
- 구간: `0~40 과소` / `41~75 적정` / `76~100 과다(탄 피자)`
- 100 도달 시 자동으로 실패 처리(탄 피자)
- 게이지 색: 초록(적정)으로 바뀌는 순간이 타이밍 포인트
- 난이도 상승 시 적정 구간 폭을 좁힘

### 6.4 손님 & 실패 조건
- 손님은 주문당 제한 시간(기본 45초)을 가짐, 시간 초과 시 이탈 → 목숨 -1
- 목숨 3개, 모두 소진 시 게임 오버
- 점수는 게임 오버 시 로컬 저장(`localStorage`)으로 최고 점수 갱신

### 6.5 진행 구조
- 스테이지 = 주문 5개 처리 단위
- 스테이지 클리어 시 짧은 결과 화면 + 다음 스테이지
- 5스테이지마다 "바쁜 시간대" 이벤트(제한 시간 20% 감소, 점수 1.5배)

## 7. 그래픽 & 사운드 방향

### 7.1 비주얼 스타일
- **플랫 2D + 두꺼운 외곽선**의 카툰 스타일
- 제한 팔레트: 크림(#FFF3E0), 토마토(#E53935), 치즈(#FFC107), 바질(#43A047), 도우(#D7A86E), 먹색(#3E2723)
- 리소스 없이 시작: Canvas 도형(`arc`, `roundRect`)으로 도우/토핑 표현
  - 도우: 갈색 원 + 살짝 불규칙한 테두리
  - 소스: 반투명 빨간 원
  - 치즈: 노란 물방울 패턴
  - 페퍼로니: 빨간 원 + 작은 점
  - 버섯: 반원 조합
- 피드백 애니메이션: 토핑 드롭(튕김), 점수 팝업(+120), 콤보 시 화면 흔들림

### 7.2 사운드
- 외부 파일 없이 **Web Audio API 합성음**으로 시작
  - 클릭: 짧은 사인파 블립
  - 성공: 상승 2음
  - 실패: 하강 버즈
- BGM은 1차에서 제외, 필요 시 무료 루프 음원 사용

## 8. 기술 스택 & 아키텍처

### 8.1 권장 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 렌더링 | **HTML5 Canvas 2D** | 가볍고 의존성 없음, 플래시 감성 구현에 충분 |
| 언어 | **Vanilla JavaScript (ES Modules)** | 빌드 도구 없이 바로 실행 |
| 게임 루프 | `requestAnimationFrame` + 고정 타임스텝 | 단순·예측 가능 |
| 사운드 | Web Audio API | 리소스 파일 불필요 |
| 저장 | localStorage | 최고 점수/설정 |
| 빌드 | 없음 (정적 파일) 또는 Vite(선택) | MVP는 더블클릭 실행 우선 |

> 대안: 씬 전환이 많아지면 **Phaser 3**로 전환. 단, MVP는 의존성 없는 Canvas를 권장.

### 8.2 구조 설계

```
Game (상태 머신)
 ├─ states: Loading → Title → Playing → Result → GameOver
 ├─ systems: OrderSystem, BakeSystem, ScoreSystem, AudioSystem
 ├─ entities: Pizza, Topping, Customer, Order
 └─ ui: HUD, OrderPanel, OvenGauge, Buttons
```

- **상태 머신**으로 화면 전환 관리 (한 번에 하나의 상태만 활성)
- **데이터 주도**: 재료/레시피는 JS 객체(또는 JSON)로 분리 → 밸런싱 용이
- 엔티티는 `update(dt)` / `render(ctx)` 인터페이스로 통일

## 9. 개발 일정 (1인 기준)

| 단계 | 기간 | 산출물 | 완료 기준 |
|---|---|---|---|
| **M1. 기반 세팅** | 1일 | index.html, 게임 루프, 상태 머신, 캔버스 스케일 | 타이틀 화면이 뜨고 Playing 전환됨 |
| **M2. 피자 제작** | 2일 | 도우/소스/토핑 배치, 드래그앤드롭 | 주문서대로 피자를 만들 수 있음 |
| **M3. 오븐 & 판정** | 1~2일 | 굽기 게이지, 정확도 계산, 점수/콤보 | 한 주문의 성공/실패가 점수로 반영됨 |
| **M4. 게임 흐름** | 1일 | 손님, 타이머, 목숨, 게임 오버, 재시작 | 한 판이 처음부터 끝까지 진행됨 |
| **M5. 폴리시** | 2일 | 사운드, 애니메이션, HUD, 최고 점수, 밸런싱 | 3분 연속 플레이 시 버그 없음 |
| **M6. QA & 배포** | 1일 | 체크리스트 점검, 정적 배포(GitHub Pages 등) | 링크로 접속해 플레이 가능 |

**총 8~9일 (버퍼 포함 2주)**

## 10. 리스크 & 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 조작이 뻑뻑해 손맛이 없음 | 핵심 재미 상실 | M2에서 드래그 히트박스·스냅을 충분히 테스트, 클릭 대체 입력 제공 |
| 그래픽 리소스 부족으로 허전함 | 완성도 저하 | 도형 + 그림자 + 파티클(치즈 가루, 김)로 밀도 보완 |
| 밸런스 붕괴(너무 쉽거나 어려움) | 재미 저하 | 모든 수치를 `config.js`에 집중, 3회 플레이 테스트로 조정 |
| 범위 확장(스코프 크리프) | 일정 지연 | MVP 체크리스트 외 기능은 "이후 확장"으로 고정 |
| 모바일에서 드래그 불가 | 접근성 저하 | Pointer Events 사용, 터치/마우스 동시 지원 |

## 11. 테스트 체크리스트

- [ ] 새로고침 후 바로 플레이 가능 (에러 없음)
- [ ] 주문과 다른 피자를 서빙하면 감점/실패 처리됨
- [ ] 오븐 게이지 3구간 판정이 정확함
- [ ] 제한 시간 초과 시 손님이 이탈하고 목숨이 줄어듦
- [ ] 목숨 0 → 게임 오버 → 재시작 시 상태가 완전히 초기화됨
- [ ] 최고 점수가 새로고침 후에도 유지됨
- [ ] 콤보가 성공 시 증가, 실패 시 0으로 초기화됨
